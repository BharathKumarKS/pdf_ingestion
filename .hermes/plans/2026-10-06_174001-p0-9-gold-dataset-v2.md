### 2.1 The power analysis (measured, 2026-10-06)

**Method.** Paired design — every query is scored under both configurations, so the test
consumes the SD of the **per-query difference** (`σ_d`), *not* the SD of the scores. Both
were measured from `data/eval_results/merge-ab_*.json` (reranker ON vs OFF, same 23 queries,
pinned HyDE):

| quantity | value |
|---|---|
| SD of per-query scores | 0.289 |
| **SD of the per-query difference `σ_d`** | **0.2315** |
| observed effect (reranker ON − OFF) | **−0.0828** |

`σ_d` is large because the reranker is a **high-variance intervention** — it helps some
queries a lot and hurts others. Compare the *merge* question (ColBERT-judge vs RRF-3),
where `σ_d = 0.118`, roughly half: those two merges agree on most queries. High `σ_d` is
what makes the reranker question expensive to settle.

**Formula** (two-sided, α=0.05, power=0.80):

```
N = (z_{α/2} + z_β)² · σ_d² / δ²
  = (1.9600 + 0.8416)² × 0.2315² / δ²
  = 0.4206 / δ²
```

| effect `δ` to detect | required N |
|---|---|
| 0.15 | 19 |
| 0.10 | 43 |
| **0.083** (what we observed) | **62** |
| 0.06 | 117 |
| 0.05 | 169 |
| 0.04 | 263 |

**The minimum to make the observed effect significant.** Solving
`1.96 · σ_d/√N < |observed|` directly:

```
N_min = ceil( (1.96 × 0.2315 / 0.0828)² ) = 31
```

| N | CI on the observed effect | verdict |
|---|---|---|
| **23 (today)** | −0.0828 ± 0.0946 → **[−0.177, +0.012]** | **not significant — spans zero** |
| **31** | −0.0828 ± 0.0815 → [−0.164, −0.001] | **significant** |
| 60 | −0.0828 ± 0.0586 → [−0.141, −0.024] | significant |
| 170 | −0.0828 ± 0.0348 → [−0.118, −0.048] | significant |

**So: 31 queries.** We are 8 short of significance on the reranker question *right now*.

**⚠️ Why 31 is not the number to plan with.** A 23-query estimate is unreliable — its own CI
is ±0.095, so the true effect could plausibly be **0.04, which needs 263**. Sizing to an
effect you measured on 23 queries is the classic pilot-study trap. Two ways out, and the
plan uses both:

1. **Plan conservatively** for a modest effect: **N = 170** (δ=0.05).
2. **Use a sequential design** — run 40, check whether the CI excludes 0, extend in blocks
   of 30 until it does (or until 170). If the effect is as large as observed you stop near
   ~40–60; if it is small you keep going. This is strictly more efficient than fixing N in
   advance and is the honest way to handle an uncertain effect size.

**Per-category and negatives use different formulas** (different estimands):

| what | estimand | formula | min |
|---|---|---|---|
| overall ranking | mean (paired) | `0.4206/δ²` | 31 / 170 |
| a per-type recall | mean | `1.96·σ/√n < 0.12` with σ≈0.30 | **25 per type** |
| abstention on negatives | **proportion** | `1.96·√(p(1−p)/n)` | **35 negatives** (±10–12 pp) |

Per-type numbers are therefore **descriptive**, not testable: detecting a 0.10 *difference
between* types at σ=0.30 would need 71 per type (213 total) — out of budget, and say so
rather than pretending otherwise.

**Suggested composition (170 total):**

| category | n | basis |
|---|---|---|
| factual | 45 | ±0.09 per-type |
| **overview** | **50** | oversampled — MRR 0.191 is the worst metric in the system |
| multihop | 40 | ±0.09 |
| visual | 15 | calibrate the 7 inherited + 8 more |
| **answerable subtotal** | **150** | |
| negatives (3 tiers) | **20** | → total 170; **raise to 35 if abstention precision matters more than ranking power** |

> **The tradeoff in one line:** ranking power wants the negatives *out* (they contribute
> nothing to a recall test), abstention precision wants them *in*. At 170 total you cannot
> have both — pick which decision matters more, or accept ~±14 pp on abstention.

## 4. Architecture / proposed approach

Extend the existing `generate_gold_dataset.py` rather than writing a new generator, because
its page→question direction is already correct — it avoids circular calibration (finding
pages for questions) by generating questions *from* known pages. Three additions: a
**multi-page strategy** for overview/multihop queries (D5), a **scan-expansion pass** that
reuses `validate_eval_calibration.scan_query` to widen each question's `relevant_pages`
beyond its source page (D4), and a **negative generator** whose candidates are accepted only
if a full scan finds **no** YES page (D2). Then teach `evaluate_rag.py` one new metric —
abstention — and keep the old file untouched for comparability (D6).

```
   EXISTING (keep)                    NEW
   ───────────────                    ───
   sample chunks stratified           sample 2–3 DISTANT pages ──► multi-page question
        │                                    │
        ▼                                    ▼
   page ──► factual question          (both paths)
        │                                    │
        └──────────────┬─────────────────────┘
                       ▼
            scan_query() over ALL 968 pages   ◄── reuses validate_eval_calibration.py
                       ▼
            relevant_pages = every YES page   (was: the 1 source page)
                       ▼
                  data/eval_queries_v2.json

   SEPARATELY:  negative candidates ──► scan_query() ──► accept ONLY if zero YES pages
```

### Task 1 — Measure the required sample size from existing data (D1)

**Create `scripts/required_n.py`:**

```python
#!/usr/bin/env python3
"""How many eval queries do we need? Computed from real per-query results.

A paired comparison needs N ≈ (z_a + z_b)^2 * sigma_d^2 / d^2, where sigma_d is the SD of
the PER-QUERY DIFFERENCE between two configurations -- not the SD of the scores. If two
configurations agree on most queries, sigma_d is small and N is small.

Usage:
    uv run python scripts/required_n.py \
        data/eval_results/merge-ab_colbert_2026-10-06.json \
        data/eval_results/merge-ab_rrf3_2026-10-06.json --delta 0.05
"""
from __future__ import annotations

import argparse
import json
import math
import sys
from pathlib import Path


def per_query_recall(path: Path, k: int = 20) -> dict[str, float]:
    """id -> recall@k for one run's JSON."""
    d = json.loads(path.read_text())
    rows = d["results"] if isinstance(d, dict) and "results" in d else d
    out: dict[str, float] = {}
    for r in rows:
        m = r.get("metrics") or {}
        v = m.get(f"R@{k}")
        if v is None:
            v = m.get("recall_at_20")
        if v is None:
            continue
        out[r["id"]] = float(v)
    return out


def main() -> int:
    p = argparse.ArgumentParser()
    p.add_argument("a"); p.add_argument("b")
    p.add_argument("--delta", type=float, default=0.05,
                   help="effect size you want to detect (default 0.05 recall@20)")
    p.add_argument("--k", type=int, default=20)
    args = p.parse_args()

    A, B = per_query_recall(Path(args.a), args.k), per_query_recall(Path(args.b), args.k)
    shared = sorted(set(A) & set(B))
    if len(shared) < 5:
        print(f"only {len(shared)} shared queries — cannot estimate; check the JSON shape")
        print(f"  keys in {args.a}: {list(A)[:5]}")
        return 1

    diffs = [A[q] - B[q] for q in shared]
    n = len(diffs)
    mean_d = sum(diffs) / n
    var_d = sum((x - mean_d) ** 2 for x in diffs) / (n - 1) if n > 1 else 0.0
    sd_d = math.sqrt(var_d)
    sd_a = math.sqrt(sum((A[q] - sum(A.values()) / n) ** 2 for q in shared) / (n - 1))

    z_a, z_b = 1.959964, 0.8416212   # alpha=0.05 two-sided, power=0.80
    need = (z_a + z_b) ** 2 * var_d / (args.delta ** 2)

    print(f"shared queries          : {n}")
    print(f"mean difference         : {mean_d:+.4f}")
    print(f"SD of per-query scores  : {sd_a:.4f}")
    print(f"SD of per-query DIFF    : {sd_d:.4f}   <-- this is what matters")
    print(f"correlation of the two  : {1 - var_d / (2 * sd_a ** 2):.3f}")
    print()
    print(f"to detect a difference of {args.delta:+.3f} at alpha=0.05, power=0.80:")
    print(f"    required N ≈ {math.ceil(need)}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

```python
_MULTI_PROMPT = """\
You are building a physics RAG evaluation dataset.

Below are passages from THREE DIFFERENT, DISTANT parts of a physics textbook.

Your task: write {n} questions that CANNOT be answered from any single passage alone --
each must require connecting ideas from at least two of them.

Requirements:
- The question must name or imply both concepts, but must not say "passage" or "excerpt".
- It must be answerable from these passages COMBINED, and only from them.
- Prefer questions a student would actually ask, e.g. "How does X relate to Y?"
- Output ONLY a JSON array of strings.

Passage A (page {pa}):
{ta}

Passage B (page {pb}):
{tb}

Passage C (page {pc}):
{tc}

Output format:
["question 1", "question 2", ...]"""


def sample_distant_triples(chunks: list, n: int, min_gap: int = 60) -> list[list]:
    """n triples of chunks from widely separated pages.

    `min_gap` forces the pages apart so the questions genuinely span the book rather than
    three neighbouring paragraphs (which would be answerable from one page).
    """
    import random
    rng = random.Random(1234)
    pool = [c for c in chunks if c.page_number]
    pool.sort(key=lambda c: c.page_number)
    triples, tries = [], 0
    while len(triples) < n and tries < n * 200:
        tries += 1
        a, b, c = rng.sample(pool, 3)
        pages = sorted([a.page_number, b.page_number, c.page_number])
        if pages[1] - pages[0] < min_gap or pages[2] - pages[1] < min_gap:
            continue
        triples.append([a, b, c])
    return triples


def generate_multipage_questions(triple: list, n: int, cfg) -> list[str]:
    a, b, c = triple
    prompt = _MULTI_PROMPT.format(
        n=n,
        pa=a.page_number, pb=b.page_number, pc=c.page_number,
        ta=a.text[:700], tb=b.text[:700], tc=c.text[:700],
    )
    try:
        raw = call_llm_raw(prompt, cfg)
        start, end = raw.find("["), raw.rfind("]") + 1
        if start == -1 or end == 0:
            return []
        return [q.strip() for q in json.loads(raw[start:end])
                if isinstance(q, str) and q.strip()]
    except Exception as exc:
        logger.warning("Multipage generation failed: {}", exc)
        return []
```

```python
#!/usr/bin/env python3
"""Widen each gold question's relevant_pages to EVERY page that answers it.

The generator labels a question with the one page it came from, but a question generated
from p252 is usually also answerable from p95/p270. One-page labels understate recall: we
would be measuring the labeller, not the retriever.

Reuses the two-pass scan in validate_eval_calibration.py (stride 15, then +/-8 dense).

Usage:
    uv run python scripts/expand_gold_labels.py \
        --query-file data/eval_queries_gold.json \
        --pdf data/base_textbooks/feynman-lectures-on-physics-volume1.pdf \
        --output data/eval_queries_gold_expanded.json
"""
from __future__ import annotations

import argparse
import importlib.util
import json
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

_ROOT = Path(__file__).resolve().parents[1]


def load_scanner():
    """Import validate_eval_calibration.py (it is a script, not a module)."""
    path = _ROOT / "scripts" / "validate_eval_calibration.py"
    spec = importlib.util.spec_from_file_location("vec_under_test", path)
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod


def main() -> int:
    p = argparse.ArgumentParser()
    p.add_argument("--query-file", default="data/eval_queries_gold.json")
    p.add_argument("--pdf", default="data/base_textbooks/feynman-lectures-on-physics-volume1.pdf")
    p.add_argument("--output", default="data/eval_queries_gold_expanded.json")
    p.add_argument("--scan-stride", type=int, default=15)
    p.add_argument("--scan-window", type=int, default=8)
    p.add_argument("--limit", type=int, default=0, help="0 = all")
    args = p.parse_args()

    vec = load_scanner()
    queries = json.loads(Path(args.query_file).read_text())
    if args.limit:
        queries = queries[: args.limit]

    out = []
    for i, q in enumerate(queries, 1):
        print(f"[{i}/{len(queries)}] {q['id']}: {q['query'][:60]}")
        before = set(q.get("relevant_pages") or [])
        try:
            hits = vec.scan_query(q, args.pdf, args)
            found = {h["page"] for h in hits if h["verdict"] == "YES"}
        except Exception as exc:
            print(f"    scan FAILED: {exc} — keeping original labels")
            out.append(q)
            continue
        after = sorted(before | found)
        print(f"    pages {sorted(before)} -> {after}  (+{len(after) - len(before)})")
        q = dict(q)
        q["relevant_pages"] = after
        q["calibration_note"] = (
            (q.get("calibration_note") or "") +
            f" | scan-expanded: {len(after)} pages"
        )
        out.append(q)

    Path(args.output).write_text(json.dumps(out, indent=2, ensure_ascii=False))
    print(f"\nwrote {args.output}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

**Create `scripts/generate_negatives.py`:**

```python
#!/usr/bin/env python3
"""Generate unanswerable / out-of-scope queries and VERIFY the book cannot answer them.

Three tiers (a good guardrail must handle all three; the third is what tests precision):
  out_of_domain    — not physics at all ("What is the capital of France?")
  in_domain_absent — physics, but this book does not cover it ("What does the book say
                     about the Schrödinger equation for the hydrogen atom?")
  near_miss        — adjacent to something the book DOES cover, but the specific fact is
                     absent. These are the valuable ones.

A candidate is accepted ONLY if a full two-pass scan finds no YES page.

Usage:
    uv run python scripts/generate_negatives.py --n 24 \
        --pdf data/base_textbooks/feynman-lectures-on-physics-volume1.pdf \
        --output data/eval_negatives.json
"""
from __future__ import annotations

import argparse
import importlib.util
import json
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))
_ROOT = Path(__file__).resolve().parents[1]

_SEEDS = {
    "out_of_domain": [
        "What is the capital of France?",
        "Who wrote Pride and Prejudice?",
        "What is the boiling point of mercury in Fahrenheit?",
        "What are the rules of cricket?",
        "How do you bake sourdough bread?",
        "What is the population of Tokyo?",
        "Which company makes the iPhone?",
        "What language is spoken in Brazil?",
    ],
    "in_domain_absent": [
        "What does the book say about the Schrödinger equation for the hydrogen atom?",
        "What is the book's treatment of general relativity and curved spacetime?",
        "What does the book say about the Higgs boson and electroweak symmetry breaking?",
        "What is the book's explanation of quantum entanglement and Bell's theorem?",
        "What does the book say about the Standard Model of particle physics?",
        "What is the book's derivation of the Navier-Stokes equations?",
        "What does the book say about superconductivity and the BCS theory?",
        "What is the book's treatment of the Fourier transform in signal processing?",
    ],
    "near_miss": [
        "What numerical value does the book give for the electron's magnetic moment?",
        "What does the book say the mass of the top quark is?",
        "Which year does the book state that the laser was invented?",
        "What does the book give as the half-life of carbon-14?",
        "What value does the book use for the cosmological constant?",
        "What does the book say the speed of sound in seawater is?",
        "What does the book list as the melting point of tungsten?",
        "How many moons does the book say Jupiter has?",
    ],
}


def load_scanner():
    path = _ROOT / "scripts" / "validate_eval_calibration.py"
    spec = importlib.util.spec_from_file_location("vec_under_test", path)
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod


def main() -> int:
    p = argparse.ArgumentParser()
    p.add_argument("--n", type=int, default=24)
    p.add_argument("--pdf", default="data/base_textbooks/feynman-lectures-on-physics-volume1.pdf")
    p.add_argument("--output", default="data/eval_negatives.json")
    p.add_argument("--scan-stride", type=int, default=15)
    p.add_argument("--scan-window", type=int, default=8)
    args = p.parse_args()

    vec = load_scanner()
    accepted, rejected = [], []
    per_tier = max(1, args.n // len(_SEEDS))

    for tier, seeds in _SEEDS.items():
        taken = 0
        for q in seeds:
            if taken >= per_tier:
                break
            entry = {"id": f"neg-{tier[:3]}-{taken + 1:03d}", "query": q, "query_type": "factual"}
            try:
                hits = vec.scan_query(entry, args.pdf, args)
                yes = [h for h in hits if h["verdict"] == "YES"]
            except Exception as exc:
                print(f"  {q[:50]!r}: scan FAILED ({exc}) — skipped, not accepted")
                continue
            if yes:
                rejected.append((q, [h["page"] for h in yes]))
                print(f"  REJECT {q[:50]!r} — answered on {[h['page'] for h in yes][:4]}")
                continue
            accepted.append({
                "id": entry["id"],
                "query": q,
                "query_type": "factual",
                "answerable": False,
                "relevant_pages": [],
                "calibrated": True,
                "calibration_note": f"negative ({tier}); full scan found no YES page",
            })
            taken += 1
            print(f"  ACCEPT {q[:50]!r}")

    Path(args.output).write_text(json.dumps(accepted, indent=2, ensure_ascii=False))
    print(f"\naccepted {len(accepted)}, rejected {len(rejected)} (answered by the book)")
    print(f"wrote {args.output}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

> ⚠️ **The `near_miss` tier will mostly be REJECTED** — Feynman Vol 1 is comprehensive and
> does discuss the electron's magnetic moment (it is a famous number, g≈2) and the laser.
> That is the mechanism working correctly. If a whole tier is rejected, that is a **finding**
> about the book's coverage, not a bug. Do not force-accept.

**Step 6c — add the helper** near `compute_citation_accuracy` (around line 478):

```python
_ABSTAIN_PHRASES = (
    "not covered", "not in the provided", "cannot be answered", "no information",
    "does not discuss", "isn't covered", "is not discussed", "i don't have",
)


def _looks_like_abstention(answer: str, top_chunks: list[dict], cfg) -> bool:
    """A negative query is handled correctly if the system declines to answer.

    Two independent signals, OR-ed: the answer text declines, or the top retrieved score
    is below the configured threshold (the retrieval-side guardrail).
    """
    if answer and any(p in answer.lower() for p in _ABSTAIN_PHRASES):
        return True
    thr = getattr(cfg, "visual_score_threshold", 0.0)
    return bool(top_chunks) and float(top_chunks[0].get("score", 1.0)) < thr
```

## 7. Risks, tradeoffs, and open questions

| Risk | Mitigation |
|---|---|
| **Required N turns out to be 200+** (Task 1) | That is a real finding. Report it and decide then — do not silently generate 200 queries. If N is large, the honest move may be to accept wider CIs and say so. |
| **Scan-expansion is expensive** — 2 passes × ~968 pages per query | The existing scan is stride-15 then ±8, so ~65 + ~30 = ~95 VLM calls per query. At 120 queries that is ~11k calls. **Budget check before Task 4.** Consider `--limit` batches and caching results to disk. |
| **Near-miss negatives mostly rejected** (Task 5) | Expected — Feynman Vol 1 is comprehensive. Report the rejection rate as a coverage finding. |
| **Circularity** | Avoided by construction: questions are generated *from* pages, and negatives are verified by *scanning*, never by asking the generator. |
| **The judge is the same family as the generator** | Already handled: judge is `Qwen3-VL-8B`, generator `gpt-oss-20b` — cross-family. Keep it that way. |
| **v2 breaks comparability with all existing artifacts** | Deliberate (D6). v1 stays on disk; every artifact records which file it used. |

### Open questions for you

1. **D1** — after Task 1 reports the required N, do we accept it, or cap at some budget?
2. **D2** — is 20% negatives the right rate, and are the three tiers the right ones?
3. **D3** — are you willing to hand-verify 25 queries (roughly 1–2 hours)?
4. **Scan budget** — Task 4's ~11k VLM calls: is that acceptable, or should we expand labels only for a subset (e.g. the first 60) and reuse v1's already-calibrated labels for the rest?
5. **Do we re-run the *whole* historical A/B series on v2** (lane A/B, merge A/B), or only the reranker question? Re-running everything is ~2 hours of cluster time but makes every claim significant.
